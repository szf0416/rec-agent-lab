## 一、这一层到底在解决什么问题

一句话：**把原始日志变成「模型可以安全训练和评估」的数据，同时保证不偷看未来。**

推荐系统的评测比 CV/NLP 更微妙：CV 的测试集是独立的图片，而推荐系统的测试集是**同一批用户后来的行为**。
一旦切分或采样出错，模型就会"偷看"到未来，指标虚高，上线后崩盘。

面试官最爱在这一点上追问，因为它区分「跑通过论文代码」和「真的理解推荐系统」。

## 二、核心设计一：时间切分（`splits.py`）

### 为什么不随机切分

随机切分是把 100 万条交互打乱后按 8:1:1 切开。问题：

假设用户 A 在 3 月看了《星际穿越》，这条记录被分到训练集；
A 在 4 月又看了一遍，这条被分到测试集。此时训练集里已经有「A 喜欢星际穿越」的信号，
模型在测试集上答对不代表它有预测能力——它只是**记住了答案**。

更严重的是物品侧：某部电影 5 月才上架，随机切分后它在训练集里出现，
模型学到了它的 embedding。但真实场景里，预测 3 月的行为时这部电影根本不存在。

**随机切分让测试变成了开卷考试。** 论文里报道的指标虚高，线上复现不出来。

### 我们的做法

```
时间轴 ──────────────────────────────────────────────────▶
       [──────── train 80% ────────][valid 10%][test 10%]
       max(train) < min(valid) < max(valid) < min(test)
```

三条不可违反的约束，由 `validate_no_leakage()` 强制：

1. `max(train.timestamp) < min(valid.timestamp)`
2. `max(valid.timestamp) < min(test.timestamp)`
3. 三个集合里没有完全相同的 `(user, item, timestamp)` 三元组

**违反任意一条 → 抛 `LeakageError`，整个流程中止。** 不做降级、不写警告后继续。

### 最精妙的一处：切点必须落在"严格边界"上

这是我在实现时踩坑、被测试抓出来的地方。

朴素做法是按索引切：`cut = int(n * 0.8)`。但如果同一个时间戳有 500 条交互，
切点恰好落在这 500 条的中间：

```
... ts=1000 × 500 条 ...
          ↑
        cut 落在这里
```

那么训练集里有一半 ts=1000 的记录，验证集里有另一半。
结果 `max(train.ts) == min(valid.ts)`，第 1 条约束被破坏——**同一时刻的信息泄漏了**。

正确做法是让切点落在**严格边界**上，即位置 `i` 满足 `ts[i-1] < ts[i]`：

```python
# recagent/data/splits.py
def _first_strict_boundary(timestamps, cut):
    if timestamps[cut - 1] < timestamps[cut]:
        return cut  # cut 本身就是边界
    # 否则向左找组起点、向右找组终点，取离 cut 最近的那个
```

**这里有两个实现陷阱，我都踩过：**

| 错误做法 | 为什么错 |
| --- | --- |
| 切点左移一位 | 切点落在组内部时，左移一位**仍在同组内**，照样劈开 |
| 只向右找第一个边界 | 在"组大、组数少"的数据上会一路跑到末尾，明明能切分却报无解 |

正确做法是找**离目标最近的**严格边界（左或右都行），距离相同时取左侧
（避免训练集被不必要地缩小）。

**面试可以这样讲**：「我的切分不变量是 max(train) < min(valid)，
并且用一个自实现的组边界吸附算法保证它，任何违反都会让流水线直接失败而不是静默通过。」

## 三、核心设计二：负采样的两条硬约束（`negative.py`）

推荐系统用隐式反馈训练，需要负样本（用户没交互过的物品，视为"不喜欢"）。
这里有两个极容易出错的地方。

### 约束一：候选池只能包含「训练期已存在」的物品

**错误做法**：用全量物品做候选池。

为什么错？假设物品 3000 在测试期才上架（`items_unseen_in_train = 44`，我们的真实数据里就有 44 个）。

- 它被当作负样本喂给模型 → 模型学到"物品 3000 是负类"
- 但测试时物品 3000 可能是正样本 → **训练分布与测试分布不一致**
- 而且模型在训练时"见过"它，等于提前泄露了未来会出现的物品

**正确做法**：先用训练集算每个物品的首次出现时间，只保留 `first_seen < train_max_ts` 的物品：

```python
pool = build_candidate_pool(split.train, cutoff=train_max_ts)
# 真实数据实测：3662 个物品（已排除那 44 个未来物品）
```

### 约束二：训练负样本与评测负样本必须分开设计

| 场景 | 采样方式 | 为什么 |
| --- | --- | --- |
| **训练** | 每正样本配 4 个，**排除该用户已交互物品** | 已交互的不能当负样本，否则教模型"用户喜欢的它不喜欢" |
| **评测** | 每用户固定 100 个，**对所有用户、所有模型完全相同** | 固定题集，模型的 NDCG 才可比 |

**评测负样本为什么要固定？**

如果每次评测重新随机采样，那模型 A 和模型 B 实际上是在**不同的题集上考试**。
两者 NDCG 的差异里混入了采样噪声，你无法判断是模型变好了还是运气好。

实现上，`NegativeSampler.eval_negatives()` 按 `num_neg` 做缓存，
同一实例重复调用返回完全相同的结果；不同实例只要 `seed` 相同，结果也完全相同
（有测试 `test_eval_negatives_identical_across_two_sampler_instances` 保证）。

```python
# 两个"模型"用同一 seed，拿到同一份题集
model_a = NegativeSampler(pool, seed=2024).eval_negatives(users, num_neg=100)
model_b = NegativeSampler(pool, seed=2024).eval_negatives(users, num_neg=100)
assert model_a == model_b  # 测试保证
```

**面试可以这样讲**：「我把负采样分成训练和评测两套协议。训练时排除用户已交互物品；
评测时冻结一份全模型共用的负样本集，否则不同模型的指标不可比——这是做消融实验的前提。」

### 附带设计：`popularity_aware` 采样

均匀采样会产出太多"显然不相关"的简单负样本，模型学不到细粒度判别力。
按物品频次的 0.75 次方加权采样（类似 word2vec 的负采样），能产出更多"难负样本"。

为什么是 0.75 次方而不是直接用频次？直接用频次会让头部热门物品主导采样，
长尾物品几乎采不到，模型对长尾的区分能力退化。

## 四、其他几个值得注意的设计

### 1. 原始数据只读

`assert_output_separate()` 会检查输出目录不在原始数据目录之内，否则报错。

理由：原始数据是有 md5 校验的"事实来源"。如果处理产物写进去，
下次校验就会失败，而且你分不清是数据损坏还是自己写进去的。

### 2. 下载必须校验 md5

`ML1M_SPEC` 里记录了三个文件的 md5 和字节大小（实测得出）：

| 文件 | 大小 | md5 |
| --- | --- | --- |
| `ratings.dat` | 24,594,131 | `a89aa359...` |
| `movies.dat` | 171,308 | `ef9fd9ff...` |
| `users.dat` | 134,368 | `681c0711...` |

**为什么不从 yaml 配置里读校验值**：那样会出现两处维护同一份事实，
迟早不一致。校验规格的**唯一真相**在 `download.py`。

校验失败时**抛错并拒绝使用**，绝不允许"带着坏数据继续跑"——
静默的数据损坏会让你后面几周的所有实验白做，而且极难发现。

### 3. 编码是 latin-1，不是 utf-8

官方 `movies.dat` 含法语/西班牙语字符（如 `Amélie`）。用 utf-8 读会抛
`UnicodeDecodeError`——这是新手最常见的翻车点之一。有测试
`test_latin1_encoding_survives` 专门守着。

### 4. `::` 分隔符

不是逗号也不是制表符，是双冒号。解析时字段数不符要**报出行号**，
否则在 100 万行的文件里你根本不知道哪里错了。

### 5. 可复现性的两个细节

- 排序用 `(timestamp, user_id, item_id)` 三元组，而不是只按 timestamp。
  同一时间戳内的顺序确定，同 seed 两次跑才会得到完全一样的序列。
- 缓存用 `.pkl`，但会对比原始文件 mtime，原始数据更新过就重新解析。

## 五、你可以自测的 6 个问题

读完自问，答不上来就回去看对应代码：

1. 随机切分为什么会虚高？举一个具体的泄漏路径。
2. `max(train.ts) < min(valid.ts)` 这个不变量，为什么是"无泄漏"的充要条件？
3. 切点左移一位为什么不够？什么情况下会失效？
4. 真实数据里那 44 个 `items_unseen_in_train`，如果放进负采样池会造成什么后果？
5. 评测负样本如果不固定，消融实验的结论会出什么问题？
6. 为什么负采样权重用频次的 0.75 次方，而不是直接用频次？
