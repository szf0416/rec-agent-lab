## 一、反向传播与自动微分

### Q1. 手推两层网络的反向传播 🔥🔥🔥 📎

**面试官想听**：不是背公式，而是**维度意识和链式法则的推导过程**。

设 `z1 = xW1 + b1`，`a1 = relu(z1)`，`z2 = a1W2 + b2`，`loss = mean((z2-y)²)`：

```
dz2  = 2(z2 - y) / (B · out_dim)
dW2  = a1ᵀ @ dz2
db2  = sum(dz2, axis=0)          # 沿 batch 维求和
da1  = dz2 @ W2ᵀ
dz1  = da1 ⊙ relu'(z1)           # 逐元素乘
dW1  = xᵀ @ dz1
db1  = sum(dz1, axis=0)
```

**维度自检法**（答题时说出来，面试官会认可）：
每个梯度必须与对应参数**形状一致**。`W1` 是 `(in, hidden)`，
`xᵀ @ dz1` 是 `(in, batch) @ (batch, hidden) = (in, hidden)` ✓

**📎 你的证据**：`from_scratch/02_manual_gradient.py` 实现了全部 6 个梯度；
`03` 验证与 PyTorch 最大误差 **2.78e-17**（float64）。

### Q2. `loss.backward()` 到底做了什么？ 🔥🔥🔥

**参考答案**：
1. 前向过程中 PyTorch 动态构建**计算图**（DAG），记录每个张量的运算和依赖关系
2. `backward()` 从 loss 出发反向遍历该图，对每个节点施加链式法则
3. 中间结果被缓存（因为反向需要），这也是为什么训练比推理占显存
4. 梯度写入**叶子张量**的 `.grad`（非叶子节点默认不保留，需 `retain_grad()`）

**追问：为什么需要 `retain_grad()`？**
因为默认只保留叶子节点的梯度——中间张量被视为"用完即可释放"。
调试或验证时需要显式调用。生产训练代码一般不用（额外占显存）。

**更好的做法**：用 `torch.autograd.grad(loss, a1_t)` 直接取对指定张量的梯度，
不走 `.grad` 属性，也不占额外显存。

**📎 你的证据**：`03` 中对 `z1_t / a1_t / z2_t` 都调用了 `retain_grad()`。

---

### Q3. 为什么每个 step 都要 `optimizer.zero_grad()`？ 🔥🔥🔥 📎

**参考答案**：PyTorch 的 `.grad` 是**累加**而非覆盖。
不清理的话，第 N 步的梯度是前 N 步的总和，等价于把学习率悄悄放大了 N 倍。

**📎 你的证据**：`01_autograd_basics.py` 实验 4 实测
`x=1` 时连续两次 `backward()`：`.grad` 从 2.0 变成 4.0，**证明是累加**。

**加分回答**：梯度累加本身是被刻意设计的特性，用于**模拟大 batch**：
显存不够时，累积 N 个 micro-batch 的梯度再 `step()` 一次。

```python
for i, batch in enumerate(loader):
    loss = model(batch) / accum_steps
    loss.backward()
    if (i + 1) % accum_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
```

### Q4. 计算图什么时候释放？为什么要 `torch.no_grad()`？ 🔥🔥

**参考答案**：
- 计算图在 `backward()` 后自动释放（除非 `retain_graph=True`）
- 推理时不需要梯度，用 `torch.no_grad()` 或 `torch.inference_mode()`
  关闭图的构建，可显著省显存、提速
- 评测代码里忘记加 `no_grad` 是常见性能问题：显存不释放会 OOM

**追问：`no_grad` 和 `inference_mode` 的区别？**
`inference_mode` 更彻底（连版本计数都不记录），更快，但张量不能再用于需要梯度的计算。

## 二、激活函数

### Q5. ReLU 在 x=0 处的导数是什么？ 🔥🔥 📎

**参考答案**：数学上不可导。工程上必须**约定**，主流框架约定为 **0**。

**📎 你的证据**：我实测过 PyTorch 的行为：

```
z = 0.0    -> grad = 0.0
z = -1e-30 -> grad = 0.0
z = 1e-30  -> grad = 1.0
```

你的实现用 `np.where(z > 0, 1.0, 0.0)`，与 PyTorch 完全一致
（`03` 的 A 部分实测误差 0.00e+00）。

**这个约定在数值梯度检验时会出问题**（见 Q6）。

---

### Q6. 数值梯度检验有什么坑？ 🔥🔥 📎 📎

**这是个高区分度的问题，大部分候选人答不出第二层。**

**第一层**：中心差分比前向差分精度高
（前向 O(ε)，中心 O(ε²)），ε 取 1e-4~1e-5。

**第二层（关键）**：**在不可导点做数值检验会失效。**

ReLU 在 `z=0` 处，中心差分：
```
(relu(ε) - relu(-ε)) / (2ε) = (ε - 0) / (2ε) = 0.5
```
而解析次梯度是 `0`——**差 0.5**。

**📎 你的证据**（自己构造的实验，`03_gradient_check.py`）：

| 测试点 | 解析梯度 | 数值梯度 | 误差 |
| --- | --- | --- | --- |
| 含 `z1=0` 的列 | -0.34588276 | -0.34137783 | **4.50e-03** |
| 无 0 点的列 | 0.00175693 | 0.00175693 | **5.21e-12** |

**相差 9 个数量级**。

**工程对策**：数值检验时跳过 `|z| < ε` 的元素，或确保随机初始化下
（恰好为 0 的概率极低）不在不可导点附近采样。

### Q7. sigmoid / tanh 为什么会导致梯度消失？ 🔥🔥🔥 📎

**参考答案**：
- `σ'(x) = σ(x)(1 - σ(x))`，**最大值只有 0.25**（在 x=0 处）
- 反向传播时梯度逐层相乘，L 层后上界是 `0.25^L`
- 10 层就是 `0.25^10 ≈ 9.5e-7`；x 偏离 0 时衰减更快

**📎 你的证据**：`01` 实验 5 实测 `sigmoid` 在 `x=10` 处导数 = **4.54e-05**。
`0.25^10` 与 `4.54e-5` 对比，能让面试官看到你真的算过。

**为什么 ReLU 缓解了这个问题**：正区间导数恒为 1，**不衰减**。
代价是负区间梯度为 0，可能出现"神经元死亡"。

**追问：残差连接怎么帮助梯度流动？**
`y = F(x) + x`，则 `∂y/∂x = ∂F/∂x + 1`。
那个 `+1` 提供了**梯度直通路径**，即使 `∂F/∂x` 衰减到 0，梯度仍能回传。
这是 ResNet 能训练上百层的核心原因。

## 三、优化器与训练技巧

### Q8. SGD / Momentum / Adam 的区别？ 🔥🔥🔥

| 优化器 | 核心思想 | 优点 | 缺点 |
| --- | --- | --- | --- |
| SGD | 沿负梯度方向走 | 简单；泛化有时更好 | 震荡；对 lr 敏感 |
| Momentum | 累积历史梯度作"惯性" | 抑制震荡；加速收敛 | 多一个超参 |
| Adam | 一阶矩 + 二阶矩自适应 | 收敛快；对 lr 不敏感 | 有时泛化差于 SGD；内存占用高 |

**追问：为什么 Adam 有时泛化不如 SGD+Momentum？**
一种解释：Adam 的自适应步长在训练后期会放大噪声，导致收敛到"尖锐"的极小值，
而尖锐极小值泛化差。相关改进：AdamW（解耦权重衰减）、SWA 等。

**面试建议**：如果你没做过对比实验，**别编数字**。
说"我项目里跑过一轮对照，用的是 ML-1M + SASRec 的设置"——
S3 阶段你会真的跑这个实验。

### Q9. 学习率太大/太小会怎样？ 🔥🔥

- **太大**：loss 震荡甚至发散（NaN）；在 loss 曲线上表现为尖峰
- **太小**：收敛极慢；可能早停在某个平坦区
- **诊断**：先跑一个 lr range test，观察 loss 随 lr 的变化，取"下降最快但未发散"的量级

**加分**：提到 warmup——训练初期梯度方向不稳定，用较小 lr 预热，
之后升到目标值再衰减。Transformer 训练的标准做法。

### Q10. 什么是梯度裁剪？为什么需要它？ 🔥🔥 📎

**参考答案**：当梯度范数超过阈值时按比例缩小，防止梯度爆炸。

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=5.0)
```

**为什么推荐模型特别需要**：
embedding 层梯度容易爆炸——热门物品被大量交互，其 embedding 梯度累积很大，
一次更新就可能跳到一个坏区域，导致 loss 突然 NaN。

**追问：`clip_grad_norm_` 和 `clip_grad_value_` 的区别？**
- `norm_`：按**总范数**等比缩放所有梯度，保持方向不变（推荐）
- `value_`：逐个元素截断到 `[-v, v]`，会改变梯度方向

**📎 你的证据**：S1-W2 任务卡要求实现并测试梯度裁剪，
测试项 #3 会验证"构造超大梯度，确认裁剪后 norm ≤ 阈值"。

## 四、训练循环工程

### Q11. 为什么用回调（Callback）而不是把 early stop 写进训练函数？ 🔥🔥 📎

**参考答案**：
1. **开闭原则**：新增功能（MLflow 记录、LR 监控、梯度统计）不改 `Trainer`
2. **可测试**：回调是独立对象，可以脱离真实训练做单元测试
3. **可组合**：不同实验用不同回调组合，靠配置驱动
4. **关注点分离**：`Trainer` 只管"训练流程"，策略属于回调

**判断抽象是否合格的方法**（面试可以主动说）：
"接 MLflow 时如果发现需要改 `Trainer`，说明抽象漏了。"

**📎 你的证据**：S1-W2 的 4 个回调设计。

### Q12. `EarlyStopping` 的正确实现有哪些容易忽略的点？ 🔥🔥 📎

**三条，第三条最多人漏**：

1. **based on 验证集而非训练集**——否则过拟合会被当成"效果好"
2. **patience 计数与"最优"比较要严格**——用 `>` 还是 `>=` 会影响触发时机
3. **⛔ 必须恢复最优权重**

第三条最致命。很多实现只"停止"不"恢复"：

```
epoch 10: NDCG 0.31   ← 最优
epoch 11: NDCG 0.30
epoch 12: NDCG 0.295  ← patience 用完，停止
```

停止时模型停在 epoch 12，**你丢掉了最好的那个**。

**正确做法**：`EarlyStopping` 内部保存最优权重快照，触发时恢复。

**📎 你的证据**：S1-W2 验收测试 #6 专门验证"停止后模型参数等于最优 epoch 的"。

### Q13. scheduler 的 `step()` 该在哪调用？ 🔥🔥 📎

**这是个隐藏的坑，答对能加分。**

| 类型 | 例子 | 何时 `step()` |
| --- | --- | --- |
| per-epoch | `StepLR`、`MultiStepLR` | 每个 epoch 结束 |
| per-step | `OneCycleLR`、`CosineAnnealingWarmRestarts` | 每个 batch 之后（**optimizer.step() 之后**）|

**用错的后果**：`OneCycleLR` 本该 1000 步走完的曲线被压缩到 10 步，
学习率曲线完全不是你想要的，而且**不会报错**。

**工程对策**：配置里显式声明 `interval: step | epoch`，
并对已知的 per-step 调度器做类型检查报警。

**📎 你的证据**：S1-W2 验收测试 #4 验证调用次数。

## 六、三条答题原则

1. **先说结论，再给理由，最后给证据。**
   例："ReLU 在 0 处约定导数为 0。因为数学上不可导，工程上必须约定，
   PyTorch 实测返回 0，我的实现用 `np.where(z>0,1,0)` 与之一致。"

2. **有数字就说数字。**
   "误差 2.78e-17" 比 "误差很小" 有说服力一个量级。

3. **不知道就说不知道，然后给出你会怎么查。**
   "这个我没实测过。如果要做，我会先构造一个最小复现案例……"
   比瞎编强得多——面试官几乎一定能识破编造。
