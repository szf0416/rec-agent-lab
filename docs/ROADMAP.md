## S0 · 环境与仓库骨架（1 周）

**目标**：把"能跑"这件事一次性解决，之后不再为环境浪费时间。

### 任务

1. 建 conda 环境 `recagent`（Python 3.11），固定 PyTorch 版本
2. 建目录骨架（见 README 仓库结构）
3. `pyproject.toml` + `ruff` + `pytest` + `pre-commit`
4. GitHub Actions：lint + test（先跑通空测试）
5. 数据下载脚本：MovieLens-1M（已在本地，脚本要能重新下载）
6. 实验配置系统（Hydra 或简单 yaml + dataclass）
7. 日志与实验追踪：MLflow 或 W&B（本地 MLflow 即可）

### 验收标准

- [ ] 新机器上 `conda env create -f environment.yml && pytest` 全绿
- [ ] `python scripts/download_data.py --dataset ml-1m` 能拿到数据并校验 md5
- [ ] 配置改一个 yaml 就能换模型/数据集，不用改代码
- [ ] CI 在 push 时自动跑 lint + test
- [ ] MLflow UI 能看到一次空跑的实验记录

### 交付给我评审的内容

- `pyproject.toml` 依赖是否最小且锁版本
- 配置系统的抽象是否过度设计（我倾向"够用就好"）
- `scripts/` 与 `recagent/` 的职责边界是否清晰（脚本只做编排，逻辑必须在包里）

## S3 · 推荐模型：召回 + 排序（8 周）

**目标**：这是项目的地基。没有它，后面的 Agent 就是空中楼阁。

### 数据集决策

| 数据集 | 用途 | 理由 |
| --- | --- | --- |
| **MovieLens-1M** | 主数据集 | 本地已有；100 万评分；6GB 显存完全够；社区基线多，好对比 |
| **Amazon Reviews (Electronics 子集)** | 冷启动 / 长尾实验 | 稀疏度高，能验证 Agent 在冷启动上的价值 |

### 切分方式（关键设计）

**必须用时间切分，不能用随机切分**。这是推荐系统面试的高频考点，也是 Agent 场景的真实前提。

```
用户历史序列 ──├── 训练 (前 80% 时间) ──├── 验证 (中 10%) ──├── 测试 (后 10%)
```

同时构造 **leave-one-out** 切分用于和论文基线对齐，两种切分都要支持。

| 周 | 主题 | 具体任务 | 产出 |
| --- | --- | --- | --- |
| W11 | 数据管线 | 时间切分、负采样策略、序列构造、特征工程 | `recagent/data/` |
| W12 | 基线召回 | Popularity、ItemCF、UserCF、矩阵分解 (BPR) | `recagent/models/recall/` |
| W13 | 双塔召回 | 双塔 + 负采样 + FAISS 向量检索 | `recagent/models/recall/two_tower.py` |
| W14 | 序列召回 SASRec | 用 S2 的 Transformer 做序列推荐（自注意力 + 因果 mask） | `recagent/models/recall/sasrec.py` |
| W15 | 精排 DIN | Attention 建模用户兴趣多样性；特征交叉 | `recagent/models/rank/din.py` |
| W16 | 多路召回融合 | 多路召回 → 去重 → 粗排 → 精排 的完整编排 | `recagent/engine/pipeline.py` |
| W17 | 调参与消融 | 超参搜索；每路召回的边际贡献 | `reports/s3_ablation.md` |
| W18 | 评测体系 | Recall@K / NDCG@K / HR@K / MRR / 覆盖率 / 多样性 | `recagent/eval/metrics.py` |

### 评测指标（全部自己实现，不用库）

- 准确性：Recall@K、NDCG@K、HR@K、MRR
- 系统性：**覆盖率**（推荐了多少不同物品）、**多样性**（类目分布）、**新颖性**
- 工业指标：P99 延迟、QPS

> 自己实现指标是刻意的：面试问"NDCG 怎么算、为什么这么算"，背公式和写出来是两回事。
> 用 RecBole 做**交叉校验**（你的 `recbole-ml1m-amazon` 仓库正好能派上用场），保证实现正确。

### 验收标准

- [ ] 时间切分与 leave-one-out 两种切分都能跑，且结果可对比
- [ ] 指标实现与 RecBole 结果对齐（误差在合理范围，有对照表）
- [ ] SASRec 在 ML-1M 上 NDCG@10 达到合理水平（目标 ≥ 0.16，低于此要分析原因）
- [ ] DIN 相比 SASRec 有提升，且给出提升来源分析
- [ ] 多路召回融合后指标**优于任何单路召回**
- [ ] 有完整的消融表：每路召回去掉后指标掉多少
- [ ] 训练可复现：同 seed 跑两次结果一致（有 CI 断言）

### 交付给我评审的内容

- 负采样策略（这是召回质量的决定因素，最容易出错）
- 时间切分的边界处理（是否有信息泄漏 —— 我会重点查这个）
- 指标实现（逐行核对公式）
- 消融实验的公平性

## S4 · LLM 微调（6 周）

**目标**：把通用大模型变成"懂推荐、懂这个数据集的助手"。这是简历上最值钱的一段。

### 模型与硬件决策

| 项 | 决策 | 理由 |
| --- | --- | --- |
| 基座模型 | **Qwen2.5-1.5B-Instruct**（本地） / **Qwen2.5-7B-Instruct**（云） | 中文好、生态成熟、1.5B 能在 6GB 上 QLoRA |
| 微调方式 | **QLoRA**（4bit 量化 + LoRA） | 6GB 显存唯一可行方案 |
| 云 GPU | AutoDL / 阿里云 单卡 A10 或 4090，按小时计费 | 几百元预算足够跑 7B LoRA 若干次 |
| 训练框架 | transformers + peft + trl | 主流，面试认可度高 |

> 也可以顺带用你已有的 `llm-lab` 环境（Python 3.11 + torch cu126），能省一次配环境。

| 周 | 主题 | 具体任务 | 产出 |
| --- | --- | --- | --- |
| W19 | 数据构造 | 把 ML-1M 构造成指令数据：用户画像→推荐请求→推荐理由 | `recagent/llm/data_builder.py` |
| W20 | SFT 第一版 | QLoRA 微调 1.5B；跑通训练、保存、加载、推理 | `recagent/llm/sft.py` |
| W21 | 效果诊断 | 微调前后对比；过拟合/灾难性遗忘检查 | `reports/s4_sft_analysis.md` |
| W22 | 7B 云上训练 | 上云跑 7B LoRA；记录显存、时长、成本 | `reports/s4_cloud_training.md` |
| W23 | 偏好对齐 (DPO) | 构造偏好对（好推荐 vs 坏推荐），DPO 训练 | `recagent/llm/dpo.py` |
| W24 | 推荐助手封装 | 统一推理接口；prompt 模板管理；结构化输出约束 | `recagent/llm/assistant.py` |

### 指令数据设计（核心难点）

三类任务混训，这是让模型"真的懂推荐"的关键：

1. **偏好理解**：用户自然语言 → 结构化偏好（类型/年代/导演/避雷）
2. **推荐生成**：用户画像 + 候选列表 → 排序后的推荐 + 理由
3. **可解释性**：为什么推荐这个 → 引用用户历史行为作为证据

> 负样本构造要刻意：用推荐引擎产出"高分成但实际不喜欢"的样本，逼模型学会分辨。

### 验收标准

- [ ] QLoRA 微调能在 6GB 显存跑通，有显存占用记录
- [ ] 微调模型在偏好理解任务上显著优于 base 模型（有量化对比表）
- [ ] 7B 云上训练有完整记录：耗时、成本、超参、loss 曲线
- [ ] DPO 后模型输出的推荐理由更符合用户真实偏好（有人工评估 + LLM-as-judge）
- [ ] 能回答：LoRA 的 rank 怎么选？QLoRA 的 4bit 量化损失在哪？为什么会灾难性遗忘？
- [ ] 模型输出有结构化约束（JSON schema 校验），不会乱输出

### 交付给我评审的内容

- 指令数据的构造逻辑（我会检查是否有数据泄漏、模板是否过于单一）
- 训练超参设置（学习率、batch size、gradient accumulation 的等价关系）
- 评测方案：怎么证明微调真的有效，而不是 prompt 写得好

                       │          │            ▲
              调用工具  │          │ 读写记忆   │ 观察结果
                       ▼          ▼            │
        ┌──────────────────┐  ┌──────────────┐ │
        │   Tool Registry  │  │    Memory    │ │
        ├──────────────────┤  ├──────────────┤ │
        │ search_item      │  │ 短期: 对话   │ │
        │ get_user_profile │  │ 长期: 偏好   │ │
        │ recall_by_vector │  │ 情景: 历史   │ │
        │ rank_candidates  │  └──────────────┘ │
        │ explain_item     │                   │
        │ clarify_prefer   │───────────────────┘
        └──────────────────┘
                 │
                 ▼
        ┌──────────────────────────┐
        │  推荐引擎 (S3) + LLM (S4/S5) │
        └──────────────────────────┘
