# RecAgent 四至六周可展示版本设计

日期：2026-10-28。目标岗位：Agent / 应用 AI 工程师。本文定义第一版交付范围；仓库原有 `docs/ROADMAP.md` 和 `docs/ARCHITECTURE.md` 描述长期愿景，若与本文的第一版范围冲突，以本文为准。

## 目标与验收

把现有 MovieLens-1M 数据处理与训练基础，接成一个可运行的对话式电影推荐系统。访客能输入偏好和可选的用户 ID，查看候选、最终推荐、推荐理由和工具调用记录。面试官可在无付费 API 的环境中复现基线、评测与演示；配置模型密钥后可运行真实工具调用 Agent。

第一版完成时必须同时满足：

1. 全新环境按 README 的固定命令准备数据、运行测试、启动演示；原始数据不入库。
2. 推荐基线与 Agent 使用相同训练数据和候选集合；离线准确率报告明确区分“固定负样本排序”与“全量候选推荐”。任何提升数字来自实际运行结果，不预设目标值。
3. 至少 30 条冻结的对话任务，覆盖题材偏好、排除条件、历史偏好、无历史用户、无匹配候选和工具故障。输出逐条 trace、失败分类及汇总指标。
4. 一条完整请求可以展示：输入、意图结构、每次工具调用与耗时、候选筛选、最终推荐、证据引用和回退状态。
5. CI 可离线运行，不能要求 API 密钥、GPU 或下载完整数据。数据相关集成实验在文档中给出本地运行命令。

## 三种方案与决策

选择“推荐基线 + 有边界的 Agent + 可复现评测”作为第一版。通用 RAG 问答缺少与研究方向的连接；先完成 SASRec、DIN、QLoRA、DPO、量化和多框架比较会推迟第一个可演示版本。这些保留为后续独立阶段，只有评测证明瓶颈确实在模型能力时才加入。

## 第一版系统边界

数据源为 MovieLens-1M。沿用现有时间切分、`interactions_train.csv`、`items.json`、`users.json` 和固定评测负样本。推荐只使用切分点之前可见的交互训练索引；请求中的用户历史不得包含验证或测试交互。使用影片标题和题材做内容约束；不调用外部影片资料服务，不生成无法从元数据或用户输入验证的剧情事实。

推荐引擎先实现 Popularity 和 ItemCF 两路候选，合并去重，过滤已看与显式排除项，再按可解释的打分规则排序。无历史用户走题材约束加热度回退。提供确定性 `recommend` 接口，Agent 与非 Agent 基线共享同一个引擎。现有 `SequentialRecallModel` 可作为后续模型接入点，但第一版运行不依赖其训练权重。

Agent 使用一个模型供应商无关的结构化决策接口：从用户话语解析题材、排除项、历史引用和澄清需要；在有上限的步骤中调用 `search_movies`、`get_user_history`、`recall_candidates`、`rank_candidates`。工具输入和输出用明确 schema 校验。输出中的每个电影 ID 必须来自候选集合；理由只能引用工具返回的题材、标题和训练期历史。未提供密钥时，以确定性策略运行相同工具链供演示和 CI 使用，并清楚标注该模式不是 LLM Agent。

工具调用超时、非法参数、空结果、循环调用或模型输出无法解析时，记录错误类型并终止或走推荐引擎回退。限制最大工具步数、每步候选数与 `top_k`，避免无界成本。公开 API 不接受任意路径、URL 或代码作为工具参数。

## 一次请求的数据流

`POST /recommend` 接收 `user_id?`、`query`、`top_k`、`mode`。请求验证后，Agent 或确定性策略形成结构化偏好，调用只读工具；引擎返回有来源与分数的候选；约束过滤和证据检查产出结果；API 返回 `items`、`trace_id`、`tool_trace`、`fallback_used`、`latency_ms`。请求失败返回明确的 4xx/5xx 结构化错误；模型不可用时仍可请求 `mode=baseline`。

## 评测设计

推荐评测使用现有固定时间切分与固定负样本，至少报告 Recall@10、NDCG@10、覆盖率、评测用户数和随机种子。所有模型对相同候选排序；不能把固定负样本指标写成全库推荐指标。另用冻结的对话任务评测 `constraint_pass_rate`（显式约束满足）、`grounding_pass_rate`（电影和理由可被工具输出支持）、`task_success_rate`（任务要求全部满足）、`fallback_rate`、每请求工具调用数、P50/P95 延迟和可用时的模型 token/费用。记录基线、确定性工具链和真实 LLM Agent 三种模式，逐条展示失败案例。真实 Agent 的质量结论只在相同任务集、相同候选与相同版本上比较。

测试按风险分层：单元测试覆盖切分不可见未来数据、候选去重、约束过滤、参数校验、步数上限与证据检查；小型合成数据做端到端测试；完整 ML-1M 运行产出版本化报告但不进 CI。随机性固定，LLM 输出不作为 CI 通过条件。

## 交付阶段

- 第 1–2 周：基线引擎、准确率脚本、第一张真实指标表；可从命令行推荐。
- 第 3 周：工具、决策接口、LLM 适配器、确定性回退、冻结对话任务集；可查看 trace。
- 第 4 周：FastAPI 与轻量演示、README 一键路径、CI 和第一份端到端评测；达到可投递版本。
- 第 5–6 周：失败分类、消融、性能与成本报告；依据真实数据修改简历与面试材料。

## 不纳入第一版

SASRec/DIN/双塔的完整训练比较、LoRA/DPO、量化、LangGraph 框架对照、在线 A/B、云端部署、多租户与长期记忆。它们可在第一版可复现之后按岗位方向和实测瓶颈独立扩展。

## 主要取舍

MovieLens-1M 的题材信息有限，所以自然语言理解评测只覆盖元数据可验证的偏好，不能声称理解复杂剧情或情绪。离线任务成功率不等于真实用户满意度。公开仓库能证明个人项目设计、实现和实验能力；简历须标明“个人项目”，不把离线实验描述成企业生产经验。
