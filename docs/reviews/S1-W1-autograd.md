## 二、必须改（阻塞合并）

### 🔴 问题 1：`02_manual_gradient.py` 的 `mse_loss` 引用了全局变量

```python
def mse_loss(y_pred, y_true):
    B, out_dim = z2.shape          # ← 用的是全局 z2，不是参数 y_pred
    return np.mean((y_pred - y_true) ** 2)
```

**函数签名承诺"我用你传进来的 y_pred"，实际却读了模块级全局变量 `z2`。**

为什么你没发现：在 `02` 里调用时 `z2` 正好就是 `y_pred`，两者同一个对象，所以结果正确。

实测后果：

```python
z2 = np.array([[1.0, 2.0]])            # 全局

# 形状相同的调用 → 结果正确，掩盖问题
mse_loss_bad(np.array([[3.,4.]]), np.zeros((1,2)))   # = 12.5 ✅
# 换个 batch size → 立刻炸
mse_loss_bad(np.array([[1.,2.],[3.,4.]]), np.zeros((2,2)))
#   ValueError: not enough values to unpack (expected 2, got 1)
```

**改法**：

```python
def mse_loss(y_pred, y_true):
    return np.mean((y_pred - y_true) ** 2)
```

注意 `B, out_dim` 这两个变量在 `mse_loss` 里**根本没被用到**（真正的除法在
`mse_gradient` 里做）。所以这行是无用代码 + 隐藏依赖，直接删掉。

**这类"依赖外部状态"的函数是工程代码里最难查的 bug 来源。**
单测通过、集成才炸，而且报错位置离出错位置很远。

### 🔴 问题 2：`02` 的 `relu_gradient` 原地修改了输入

```python
def relu_gradient(x):
    x[x <= 0] = 0      # ← 把调用者的数组改掉了
    x[x > 0] = 1
    return x
```

实测：

```python
z1 = np.array([[-0.5, 0.3], [0.8, -1.2]])
调用前 z1 = [[-0.5, 0.3], [0.8, -1.2]]
调用后 z1 = [[0.0,  1.0], [1.0,  0.0]]   # 原值被覆盖成 0/1
```

**`02` 里恰好没事**：`dz1 = da1 * relu_gradient(z1)` 之后 `z1` 再没被用到。

**但这是定时炸弹**：
- 调试时想 `print(z1)` 看激活前分布 → 拿到的是 0/1
- 以后加第三层、或复用 `z1` → 静默错误
- 这类 bug 不会报错，只会让结果悄悄变错

**改法**（你在 `03` 里已经写对了，把 `03` 的写法搬回 `02`）：

```python
def relu_gradient(z):
    return np.where(z > 0, 1.0, 0.0)
```

`np.where` 返回新数组，不碰输入。

**为什么 `03` 里你没犯这个错？** 因为你写 `03` 时特意加了 docstring
说明次梯度约定。这说明你**知道**该怎么做，只是 `02` 是更早写的没回头改。
好习惯：写完后回看一遍早期文件的一致性。

## 五、面试预演

面试官看到这份代码，最可能追问的 6 个问题：

**1. `retain_grad()` 是干什么的？为什么需要它？**

答：PyTorch 默认只保留叶子节点的梯度。中间计算结果（如 `a1`、`z1`）
在反向传播后 `.grad` 是 `None`，因为它们被视为"用完即可释放"。
`retain_grad()` 显式要求保留，代价是这些中间张量的梯度会占用显存直到被释放。
生产训练代码里一般不用它——只在调试/验证时用。

**2. 你不用 `retain_grad()` 能得到 `da1` 吗？**

答：能——用 `torch.autograd.grad(loss, a1_t)`，它直接返回对指定张量的梯度，
且不依赖 `.grad` 属性。这是更好的做法，因为不会额外占用显存。

**3. 你的数值梯度检验有个盲区：如果 `z1` 里恰好有元素等于 0 会怎样？**

答：中心差分会在不可导点两侧采样，得到的是 `(relu(ε) - relu(-ε))/(2ε) = 0.5`，
而解析梯度（按 PyTorch 约定）是 `0`。两者会差 0.5，测试会失败。

**这不是 bug，而是"在不可导点做数值检验"的固有困难。**
正确做法是：数值检验时**避开不可导点**（随机初始化下 `z1` 恰好等于 0 的概率几乎为 0），
或者在测试里主动跳过 `|z1| < ε` 的元素。

**建议你补一个实验**：故意把某个 `z1` 元素设成 0，观察误差从 1e-12 跳到 0.5。
这样你就真正理解了"数值检验的边界条件"，面试时能答出别人答不出的深度。

**4. 为什么用中心差分而不是前向差分？**

答：前向差分 `(f(w+ε)-f(w))/ε` 的截断误差是 O(ε)；
中心差分 `(f(w+ε)-f(w-ε))/(2ε)` 是 O(ε²)。
在 float64 下，ε 取 1e-5 时中心差分误差约 1e-10，与实测的 1e-11~1e-13 吻合。

**5. 为什么误差是 1e-19 而不是恰好 0？**

答：float64 的机器精度 ε≈2.2e-16。`dW2 = a1ᵀ @ dz2` 是 5×4 和 4×2 的
矩阵乘法，每个输出元素累加 4 次乘加，浮点舍入误差累积后落在 e-18~e-19。
`db2/db1` 是纯求和，误差为 0 说明这些计算路径上没有舍入损失。

**6. `sigmoid` 在 x=10 处导数是 4.5e-5，这意味着什么？**

答：意味着如果用 sigmoid 做激活，梯度每经过一层就衰减到这个比例。
深层网络里（比如 10 层），梯度会变成 `(4.5e-5)^10 ≈ 1e-44`，**完全消失**。
这就是为什么现代网络用 ReLU（正区间导数恒为 1，不衰减）
以及为什么需要残差连接（提供梯度直通路径）。
