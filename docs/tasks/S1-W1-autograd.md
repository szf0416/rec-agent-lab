## 一、本周要回答的一个问题

> **`loss.backward()` 到底做了什么？**

这个问题面试出现频率极高。绝大多数人能说"自动微分""链式法则"，
但让他手推一个两层网络的梯度、或者解释计算图什么时候释放，
就答不上来了。

本周的目标是让你**亲手算出梯度**，然后用 PyTorch 验证你算对了。

### 文件 1：`from_scratch/01_autograd_basics.py`

用 PyTorch 做 5 组小实验，每组打印结果并写一行注释说明你看到了什么。

| 实验 | 做什么 | 你要观察 |
| --- | --- | --- |
| 1 | 标量求导：`y = x²`，`x = 3`，看 `x.grad` | 手算 6，对比 |
| 2 | 复合函数：`y = (2x + 1)²`，`x = 1` | 链式法则结果 |
| 3 | 多变量：`z = x·y + x²`，求对 x、y 的偏导 | 两个 `.grad` 各是什么 |
| 4 | **梯度累加**：连续两次 `backward()` 不清理 | `.grad` 是累加还是覆盖？ |
| 5 | **梯度消失**：`y = sigmoid(x)` 在 `x = 10` 处求导 | 为什么接近 0 |

**实验 4 和 5 是重点**，它们直接关联面试常问的两个坑：
`optimizer.zero_grad()` 为什么必须调用；为什么深层网络用 sigmoid 会训不动。

### 文件 2：`from_scratch/02_manual_gradient.py`

**本文件是本周核心。禁止使用 `torch.autograd`。**

用纯 NumPy（或纯 Python）实现一个两层网络的前向与反向：

```
输入 x (batch, in_dim)
  ↓
z1 = x @ W1 + b1          # 线性层 1
a1 = relu(z1)             # 激活
  ↓
z2 = a1 @ W2 + b2         # 线性层 2
  ↓
loss = MSE(z2, y)
```

**你需要手写推导并实现这 6 个梯度**：

```
∂loss/∂W2,  ∂loss/∂b2,  ∂loss/∂a1,  ∂loss/∂z1,  ∂loss/∂W1,  ∂loss/∂b1
```

**关键约束**：`relu` 的导数在 `z1 = 0` 处未定义。你必须自己决定怎么处理
（返回 0？返回 0.5？），并在注释里写明**为什么这么选**。

### 文件 3：`from_scratch/03_gradient_check.py`

**验证你手算的梯度是对的。** 这是本周评分最重要的一项。

两部分验证：

**A. 与 PyTorch 对齐**

用同一组权重、同一批数据，分别跑：
- 你的 NumPy 实现 → 得到手算梯度
- PyTorch 实现（`requires_grad=True` + `backward()`）→ 得到自动微分梯度

逐个比对 6 个梯度，**最大绝对误差必须 < 1e-6**。

**B. 数值梯度检验（finite difference）**

不依赖 PyTorch，用数值近似独立验证：

```
∂loss/∂w ≈ (loss(w + ε) - loss(w - ε)) / (2ε)
```

对若干随机权重分量做扰动，比对解析梯度与数值梯度。
这是**独立证据**——如果 A 和 B 都通过，说明你的推导确实正确，
而不是"碰巧和 PyTorch 一致"。

## 四、建议路径（不要跳步）

**第 1 步：先推公式，再写代码。**

拿纸笔（或 Markdown）写出 6 个梯度的推导，标注每一步用到的链式法则。
**推导没通就不要开编辑器**——直接写代码会变成试错，学不到东西。

`z2 = a1 @ W2 + b2`，`loss = mean((z2 - y)²)`，从头推：
```
∂loss/∂z2 = 2(z2 - y)/N
∂loss/∂W2 = a1ᵀ @ ∂loss/∂z2
∂loss/∂a1 = ∂loss/∂z2 @ W2ᵀ
∂loss/∂z1 = ∂loss/∂a1 ⊙ relu'(z1)
...
```
**矩阵乘法的转置位置最容易错**，写代码前先确认每个张量的形状。

**第 2 步：实现前向，用 PyTorch 验证前向输出一致。**
先确认前向没错，再谈反向——否则梯度对不上时你分不清是哪一步的问题。

**第 3 步：实现反向，跑对齐测试。**
误差大就先看**第一个不对的那个梯度**，别一次改多处。

**第 4 步：加数值梯度检验。**
它比 PyTorch 对齐更"独立"——如果连它都通过，你就能确信推导是对的。

## 五、卡点提示（卡住 30 分钟以上就看，别硬耗）

<details>
<summary>提示 1：矩阵求导的转置怎么定</summary>

从形状反推。若 `Z = A @ W`，则 `∂L/∂W = Aᵀ @ ∂L/∂Z`。
验证方法：等号两边形状必须一致。`W` 是 `(in, out)`，
`A` 是 `(batch, in)`，`∂L/∂Z` 是 `(batch, out)`，
所以 `Aᵀ @ ∂L/∂Z` 是 `(in, out)` ✓。

**形状对不上，一定错了。**
</details>

<details>
<summary>提示 2：relu 在 0 处的导数</summary>

数学上不可导，工程上有三种常见做法：
返 0、返 0.5、返 1。PyTorch 的 `relu` 实际返 **0**。

关键不是选哪个，而是**你知道这是个选择**，并能说明影响。
用随机初始化时，`z1` 恰好等于 0 的概率极低，所以实践中差别可忽略。
</details>

<details>
<summary>提示 3：数值梯度检验的 ε 怎么选</summary>

- ε 太大（如 1e-2）：截断误差大，近似不准
- ε 太小（如 1e-12）：浮点相减灾难性抵消，结果变成噪声
- 推荐 **1e-4 到 1e-5**，并用**中心差分** `(f(w+ε) - f(w-ε)) / 2ε`
  （比前向差分精度高一阶）

用 `float64` 做数值检验，`float32` 精度不够会一直对不上。
</details>
