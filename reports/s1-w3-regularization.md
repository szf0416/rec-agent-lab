# S1-W3 实验报告：过拟合与正则化

> 目标：在**真实数据上先造出明显过拟合**，再逐个加入正则化手段，
> 看哪个能有效压缩泛化差距。
>
> 数据：MovieLens-1M（时间切分） | 模型：`SequentialRecallModel` | 硬件：RTX 3060 6GB

---

## 一、实验设置

| 项目 | 值 | 为什么这么选 |
| --- | --- | --- |
| 用户采样 | 1,800 / 5,392 | 数据少 → 容易造出过拟合 |
| 训练样本 | 44,434 对（`min_prefix=20`） | |
| 验证样本 | 22,997 条（520 用户 × 100 候选） | 覆盖全部可评测用户 |
| embedding_dim | 128 | 容量偏大（相对数据量） |
| hidden_dim | 256（MLP 打分头） | 见下文「问题 2」 |
| 训练轮数 | 12（固定，**关掉早停**） | 所有配置跑满同轮数才公平 |
| optimizer | **AdamW** | 见下文「问题 1」 |
| monitor | ndcg@10 | |
| 负样本 | 训练 99（**固定**）+ 评测 99（固定） | 见下文「问题 3」 |

### 核心度量：`gap_loss`

```
gap_loss = valid_loss(末轮) − train_loss(末轮)
```

**为什么用 gap 而不是只看 ndcg**：

- `ndcg@10` 是排序指标，噪声较大（520 用户 × 45 样本，用户间差异大）
- `gap` 直接度量**泛化差距**，是过拟合程度的一阶指标，平滑得多
- 正则化的作用就是压 gap。**gap 降 + ndcg 不降 = 有效**

## 三、四个结论

### 结论 1：dropout 是压制过拟合最有效的手段

```
baseline:  gap = 0.0117, 退步 15.4%
drop 0.5:  gap = 0.0041, 退步  4.1%    ← gap 压缩 65%
```

**机制**：dropout 随机丢弃部分历史行为（对用户向量）与物品特征，
迫使模型不依赖任何单个行为，学到更鲁棒的表示。

**代价**：train_loss 从 0.0439 升到 0.0486（训练变难了）。
**这是正则化的本质**——用训练能力换泛化能力，而这里换得很值。

### 结论 2：降容量有效，但有下限

`capacity_dim32`（embedding 128→32）把参数量从 572K 降到 143K，gap 减半（0.0117→0.0072），
且 ndcg 不降（0.1706 → 0.1706）。

但 `capacity_nomlp`（去掉 MLP 头，只留内积）**反而更差**：

```
train_loss = 0.4905   ← 是 baseline 的 11 倍
ndcg最优   = 0.1465   ← 比 baseline 低 0.024（14% 相对下降）
gap        = 0.0773   ← 反而更大
```

**为什么**：这不是"正则化"，而是**容量不足（欠拟合）**。
纯内积的表达能力太弱，连训练集都拟合不好（train_loss 0.49），
泛化差是因为模型本身不行，不是因为过拟合。

> **面试点**：区分「过拟合」与「欠拟合」的判据是 train_loss。
> train_loss 低而 gap 大 → 过拟合，该加正则；
> train_loss 本身就高 → 欠拟合，加正则只会更糟，该加容量。

### 结论 3：weight decay 对 embedding 层效果有限

三种强度（1e-3 / 1e-2 / 1e-1）的 gap 变化只有 −0.0004 ~ −0.0020，
远小于 dropout 的 −0.0077。且随强度增加 ndcg 略降。

**为什么**：weight decay 约束的是**参数范数**，而本模型的过拟合主要来自
"记住用户-物品的特定组合"（embedding 查表），不是参数范数过大。
dropout 直接破坏这种记忆，所以更对症。

### 结论 4：组合正则不是简单叠加

`combo`（wd 1e-2 + dropout 0.3）的 gap = 0.0058，**介于** dropout 0.2（0.0070）
与 dropout 0.5（0.0041）之间，且 ndcg 最优（0.1708，与 baseline 并列最高）。

**说明**：组合能达到"接近强 dropout 的泛化 + 不打折的指标"。
实际工程中优先考虑组合而非单一手段加大强度——**过强的单一正则往往伤指标**。

## 四、实验过程中踩的三个坑（这是本次最有价值的部分）

### 坑 1：评测协议不一致，导致评测信号失效

**最初的设置**：训练负样本每个 epoch 动态重采样，评测负样本固定。

**现象**：

```
epoch 0: train_loss=0.6221  valid ndcg=0.1445
epoch 9: train_loss=0.4952  valid ndcg=0.1312   ← loss 降，指标也降
```

**根因**：模型不断适应"新的随机负样本分布"，而评测用固定的 100 个候选。
**训练目标 ≠ 评测目标**，所以 loss 下降不代表评测变好。

**这不是过拟合，是协议错配** —— 评测信号无法用来比较正则化。

**修复**：训练负样本也**一次性固定**（`fixed_negatives=True`），
让训练与评测在同一套候选集协议下。

**副作用（好的意外）**：训练速度提升 **12 倍**（32 秒/轮 → 2.6 秒/轮），
因为负样本预计算一次即可复用。

> **面试可讲**：被问"训练和评测的负样本要一致吗"时，
> 可以答：**采样协议**可以不同，但**候选集是否固定**必须一致。
> 动态采样 + 固定评测会让指标失真。

### 坑 2：Adam + weight_decay 把 embedding 压死

**现象**：所有带 `weight_decay` 的配置，`train_loss` 卡在 **0.6931**。

```
0.6931 = ln(2) = BCE 在模型输出恒为 0 时的值
```

**根因**：PyTorch 的 `Adam(weight_decay=w)` 走 **L2 路径**（把 w·θ 加进梯度）。
embedding 层绝大多数行当步没有梯度，但仍被施加 L2 衰减：

```
衰减速度 ∝ weight_decay × 总参数量 = 1e-3 × 505,984
梯度更新 ∝ 仅少数被激活的行
→ 衰减速度远超梯度更新 → 整个 embedding 被压向 0
```

**修复**：改用 **AdamW**（权重衰减解耦出梯度，直接作用于参数）。

**为什么推荐系统必须用 AdamW**：embedding 是稀疏参数，
Adam 的 L2 会无差别衰减所有行（包括未被激活的行），实质上是"惩罚冷门物品"，
这与推荐系统的目标直接冲突。

> **面试点**：这是 Adam vs AdamW 最实质的区别。
> 答"AdamW 把权重衰减解耦"是及格，能补上"稀疏 embedding 上 Adam+L2 会压死参数"
> 才是真正踩过坑。

### 坑 3：模型容量不足时过拟合"观察不到"

**最初的模型**（纯内积，无 MLP 头）：

```
最优轮次 = 0，之后 12 轮单调下降
train_loss = 0.49（连训练集都拟合不好）
```

**根因**：容量太小，第 0 轮就到达能力上限，之后只能过拟合——
**观察不到"先升后降"的完整曲线**，也就无法判断正则化是否把过拟合推后了。

**修复**：加一层 MLP 打分头（`Linear(2d, 256) → ReLU → Dropout → Linear(256, 1)`），
容量提升后曲线变成：

```
epoch 1: valid_ndcg=0.1662
epoch 2: valid_ndcg=0.1706   ← 最优
epoch 11: valid_ndcg=0.1442  ← 退步 15.5%
```

**教训**：**做正则化实验的前提是先造出可观察的过拟合**。
如果模型在第 0 轮就到顶，你会误以为"正则化没用"。
