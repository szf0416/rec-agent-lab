## 二、五条结论

### 结论 1：`Adam` 与 `AdamW` 在 `weight_decay=0` 时完全相同

```
adam    0.0452 / 0.0093 / 0.1706
adamw   0.0452 / 0.0093 / 0.1706     ← 完全相同
```

**这说明我的实现没有引入额外差异**——两者的区别只在权重衰减的处理方式上，
关掉 wd 后行为必须一致。这是一个实用的「实现正确性检查」。

### 结论 2：⭐ 同样 `weight_decay=0.01`，`Adam` 崩溃而 `AdamW` 几乎无损

| 配置 | ndcg最优 | 相对无 wd 的变化 |
| --- | --- | --- |
| adam（无 wd） | 0.1706 | — |
| **adam + wd 0.01** | **0.0468** | **−73%** |
| adamw（无 wd） | 0.1706 | — |
| **adamw + wd 0.01** | **0.1705** | **−0.06%** |

**同样的衰减强度，差距 3.6 倍。**

更关键的是 `adam + wd` 的 `ndcg = 0.0468` 已经接近随机水平
（100 候选随机命中 ≈ 0.014）——**embedding 真的被压死了**。

**机制回顾**（W3 已推导，这里有了量化证据）：

```
Adam 的 wd 走 L2 路径 → 衰减项进入梯度 g ← g + w·θ
                     → 经过自适应归一化 m/√v 被放大成一次完整更新
embedding 稀疏：每 batch 只激活 ~3% 的行，但衰减作用于 100% 的行
→ 97% 的参数被单向拉向 0，且得不到梯度抵抗
```

`AdamW` 把衰减解耦成 `θ ← θ − lr·(Adam步长) − lr·w·θ`，
衰减不被自适应缩放放大，所以无损。

> **面试可讲**：这是「推荐系统必须用 AdamW」最强的实验证据。
> 不是理论推演，是**同 wd 下 0.0468 vs 0.1705 的实测对比**。

### 结论 3：SGD 在本任务明显弱于 Adam，但 momentum 有实质作用

```
sgd              ndcg=0.0493
sgd_momentum     ndcg=0.0600     ← momentum 提升 22%
adam             ndcg=0.1706     ← 但仍远低于 Adam
```

**为什么 SGD 差这么多**：

- `train_loss` 只到 0.0560（Adam 是 0.0452），说明**还没充分收敛**
- 10 轮 × lr=0.05 对 SGD 不够；SGD 通常需要更多轮数 + 精心调 lr
- 还有一个结构原因：embedding 场景下**每个参数被激活的频率差异极大**
  （热门物品 vs 冷门物品），SGD 对所有参数用同一个 lr，
  而 Adam 的自适应步长天然缓解了这个问题

> **这解释了为什么推荐系统几乎都用 Adam 系**——不只是收敛快，
> 而是**自适应性对稀疏参数更友好**。

### 结论 4：warmup 不提升精度，但显著压缩泛化差距

```
warmup_0     ndcg=0.1706   gap=0.0093
warmup_100   ndcg=0.1699   gap=0.0063
warmup_500   ndcg=0.1686   gap=0.0039    ← gap 降 58%，ndcg 只降 1.2%
```

**怎么读这个结果**：

| 观察 | 含义 |
| --- | --- |
| ndcg **略降**（−1.2%） | warmup 没有提升精度 |
| gap **显著下降**（−58%） | warmup 确实改善了泛化 |
| 最优轮**推后**（2 → 4） | 训练更稳定，过拟合来得更晚 |

**为什么**：warmup 让训练初期用很小的 lr，
避免参数在随机初始化后就被大步长推到坏区域。
这让模型最终停在更平坦的极小值上 —— **泛化更好，但精度不一定更高**。

> **面试可讲**：被问「warmup 有什么用」时，
> 多数人答「防止训练初期不稳定」。你可以补一句：
> **「我实测过，warmup 主要压泛化差距而不是提升精度——
> gap 降了 58%，但 ndcg 反而略降 1.2%。」**

**注意**：我们的模型很小（572K 参数），warmup 的收益有限。
Transformer 类模型（S2 的 Tiny GPT、S3 的 SASRec）通常更依赖 warmup。

### 结论 5：⭐ 线性缩放规则（batch ×4 → lr ×4）在本任务上不成立

| 配置 | batch | lr | ndcg最优 | gap |
| --- | --- | --- | --- | --- |
| bs128 | 128 | 1e-3 | 0.1677 | 0.0135 |
| **bs512** | 512 | **1e-3（不变）** | **0.1701** | **0.0046** |
| bs512 | 512 | 4e-3（×4） | 0.1663 | 0.0136 |

**放大 lr 反而更差**（0.1701 → 0.1663），而**保持 lr 不变**是这组最优。

**线性缩放规则的适用条件**：它来自「梯度噪声随 batch 增大而减小，
需要更大 lr 维持相同的噪声尺度」这个假设。

**但在本任务上不成立**，可能原因：

1. `bs512` 时每 epoch 的 step 数从 289 降到 72 —— **step 少了 4 倍**，
   如果同时把 lr 放大 4 倍，等效于「用大 lr 走更少步」，容易冲过头
2. `4e-3` 对 AdamW 偏大（lr range test 建议上界是 1.29e-2，看似还安全，
   但那是**平滑 loss 不上升**的上界，不代表排序质量最优）

> **面试可讲**：被问「大 batch 要不要放大 lr」时，
> 答「常见做法是按线性/平方根规则缩放，**但需要实验验证**，
> 我在自己的任务上实测线性缩放反而变差（0.1701 → 0.1663）。」

## 三、实验过程中修的三个问题

### 问题 1：⭐ 排序指标平局 bug（模型退化时显示 ndcg=1.0）

**怎么发现的**：`optimizers` 模式探针里 `adam_l2_wd0.01` 返回 `ndcg=1.0000`。
这个值不可能（完美排序），追查后确认是指标实现缺陷。

**根因**：候选集把正样本固定在第 0 列。旧实现用 `argpartition` 取 top-k，
分数全同时平局裁决沿用数组顺序 → 第 0 列被排进 top-1 → ndcg = 1.0。

```
实测旧行为：
  全 0 分数（完全退化）  hr@10=1.0000  ndcg@10=1.0000   ← 假完美
  正样本随机位置时        hr@10=0.1250  ndcg@10=0.0538   ← 随机水平
```

**危害**：**最坏的情况看起来最好**，会掩盖训练失败。

**修复**：`np.lexsort((tie_breaker, -scores))` 用固定种子的随机数破平局 +
退化检测（打分标准差 < 1e-8 时归零并报警）。

**修复的价值**：如果没有这次修复，本报告里 `adam_l2_wd0.01` 的
「ndcg = 1.0」会被当成"表现最好"，得出完全相反的结论。

### 问题 2：`OptConfig` 的 momentum 默认值陷阱

第一次跑时 `sgd` 与 `sgd_momentum` 的指标**一模一样**：

```
sgd              0.0560 / 0.0000 / 0.0600 / 9
sgd_momentum     0.0560 / 0.0000 / 0.0600 / 9   ← 完全相同
```

**根因**：`OptConfig` 的 `momentum` 字段默认值是 `0.9`，
所以 `OptConfig("sgd", ...)` 实际上也带了动量 0.9。

**修复**：显式写 `momentum=0.0`。修复后两者不同了（0.0493 vs 0.0600）。

> **教训**：**两个配置结果完全相同时，先怀疑配置重复，别当成实验噪声。**

### 问题 3：lr range test 的 `base_lr` 用法错误

第一次跑出 `下降最快处 lr = 4.16e+01`（**超过扫描上界 0.3 一百倍**）。

**根因**：`LambdaLR` 的因子是**乘法**的，实际 lr = `base_lr × factor`。
我把 `base_lr` 设成了 `1.0`，于是实际 lr 能到 `1.0 × (0.3/1e-6) = 3e5`。

**修复**：`base_lr` 设为 `lr_min`，factor 从 1 增长到 `lr_max/lr_min`。

修复后的结果合理了，**并与实验选用的 lr 交叉验证成功**：

```
lr range test 给出：下降最快处 = 7.75e-04
实际实验选用     ：lr = 1e-3          ← 同量级，说明选得合理
```

> **教训**：**结果出现越界值（超出设定范围）时，一定是实现有问题**，不要当成"模型行为异常"。
