# S1 端到端验证报告

> 目的：证明 S1 写的训练基础设施**在真实数据上真的能用**，
> 而不只是"假数据测试通过"。

- 数据：MovieLens-1M（时间切分产物，`data/processed/ml1m/`）
- 模型：`SequentialRecallModel`（物品 embedding 均值池化 + 内积打分）
- 训练循环：`recagent/train/`（S1-W2 产出）
- 硬件：RTX 3060 Laptop 6GB

## 一、数据规模

| 项目 | 数量 |
| --- | --- |
| 用户序列 | 5,392 |
| 训练交互 | 800,168 |
| 物品上限（embedding 表大小） | 3,952 |
| 负采样候选池 | 3,662（全部来自训练集） |
| 训练样本（prefix→next 对） | 131,242 |
| 验证样本 | 23,009（518 用户 × 100 候选） |
| 测试样本 | 78,119（1,002 用户 × 100 候选） |
| 模型参数量 | 252,992 |

> 训练样本量由 `min_prefix=20` 决定：序列全长展开会产出 77 万对，太慢；
> 取"前缀长度 ≥ 20"的位置，得到 13 万对，6 轮内能跑完且足够验证流程。

## 二、评测协议

```
训练：  prefix → next item，动态负采样
验证：  完整训练序列 → valid 正样本 + 99 固定负样本
测试：  完整训练序列 → test  正样本 + 99 固定负样本
```

**三条设计约束**（都在代码里落实）：

1. **训练输入绝不含标签**。`sequences_train.npz` 的序列末项就是下一个物品，
   直接用整段序列当输入会让模型抄输入。所以构造样本时 `输入=seq[:-1]`。
2. **val 与 test 的负样本各自固定**（`NegativeSampler(seed=42)`）。
   若每次重新采样，模型之间不可比；若 val 与 test 共用一套，早停会污染测试指标。
3. **早停只看 val，test 只报告一次**。用 test 调参属于"拿考试题练手"。

## 四、三个值得记录的观察

### 观察 1：训练/评测协议一致，指标反而更低

配置 B 让训练负样本数（99）与评测一致，直觉上应该更好，实测却**更差**
（0.1451 vs 0.1574）。

**原因**：负样本多 → 任务更难 → 固定容量模型 + 固定轮数下学不透。
这不是 bug，而是**任务难度与模型容量的匹配问题**。
S3 用 SASRec 时有更强的表达能力，结论可能反转——这正是值得做消融的点。

**面试可讲**：面试官常问"训练和评测的负样本数要不要一致"。
答案是**不强制**：一致性有助于减小训练/推理分布差异，
但难度提升可能让欠拟合更严重，需要用实验确定。

### 观察 2：过拟合被正确捕捉

配置 B 从 **epoch 3 开始**：

```
epoch 2: train_loss=0.5185  valid ndcg=0.1388   ← 最优
epoch 3: train_loss=0.5140  valid ndcg=0.1360   ← train 降、valid 降
epoch 5: train_loss=0.5118  valid ndcg=0.1349
```

train_loss 持续下降但 valid ndcg 持续下降——**典型的过拟合**。

这说明三件事都工作正常：
1. 验证集指标能反映泛化能力（不是跟着训练集一起变好）
2. `EarlyStopping(monitor="ndcg@10", mode="max")` 正确地把它识别为"不提升"
3. `restore_best=True` 让最终模型停在 epoch 2（0.1388），而不是 epoch 5（0.1349）

### 观察 3：单位指标水平

ndcg@10 ≈ 0.15 在 ML-1M 的「1 正 + 99 负」协议下属于**弱基线**：

- 随机猜测：1/100 的命中率，ndcg@10 ≈ 0.014
- 本模型：0.145 ~ 0.157，约为随机的 10 倍
- SASRec（S3 目标）：ML-1M 上通常能到 **0.20+**

所以这个模型的价值是"证明流程通"，**不是"效果好"**。S3 换 SASRec 后指标应有明显提升，
届时这个数字就是天然的 baseline 对照。

## 五、验证过程中暴露并修复的真问题

| 问题 | 现象 | 修复 |
| --- | --- | --- |
| 候选集长度不齐 | `torch.stack` 报 `[101] vs [100]` | 固定负样本可能与正样本重叠；改为跳过冲突项并补齐，保持长度恒定 |
| 序列含标签 | 会让模型抄输入 | 构造样本时排除末项：`输入=seq[:-1]` |
| 验证集覆盖过低 | 只用预处理产物的负样本，valid 只覆盖 387 用户 | 为 val 与 test 各自生成固定负样本 |
| `num_items` 算错 | 只按训练集上界建表，遇到测试集新物品会越界 | 取 train/valid/test 三者 item_id 的最大值 |

**这四条都是"假数据测试发现不了、只有真实数据才暴露"的问题。**
端到端验证的价值就在这里。
