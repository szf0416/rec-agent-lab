# MovieLens-1M 固定候选基线评测

日期：2026-10-28。运行时使用本仓库中的评测脚本与预处理配置；数据文件不提交 Git。

## 协议

使用 `configs/data/ml1m.yaml` 的全局时间切分和 seed 42。每用户按时间选第一个“训练期已存在且训练历史未看过”的测试电影作为正样本，与该用户冻结的 100 个负样本组成 101 个候选。评分器只看训练期交互；评测负样本在构造时排除了训练、验证、测试中的全部已知交互。两个模型的用户、正样本和负样本完全相同。同分按电影 ID 升序。

命令：

```bash
python scripts/preprocess.py --config configs/data/ml1m.yaml
python scripts/evaluate_baseline.py --processed-dir data/processed/ml1m --k 10
```

## 实测结果

测试用户 1209 人，纳入 1208 人；其中 1008 人有训练历史，200 人以热度回退。1 人的测试正样本在训练期物品目录中不存在，按协议跳过。训练期目录为 3662 部电影。

| 模型 | Recall@10 | NDCG@10 | 覆盖率 |
| --- | ---: | ---: | ---: |
| Popularity | 0.2649 | 0.1403 | 0.1040 |
| ItemCF | 0.2053 | 0.1165 | 0.1537 |

在此协议下，ItemCF 的准确率低于热度基线，但覆盖率更高。当前 ItemCF 用历史电影的余弦共现分数求和，未做历史长度归一、时间衰减或参数调优。后续应先分析有历史用户的失败样本，再决定是否调整融合权重；不能把尚未跑过的改动写成提升。

## 解释边界

这些是“1 正 + 100 负”的**采样候选排序指标**，不是从全库 3662 部训练期电影中召回的指标，也不是在线用户满意度。若改变负采样策略、正样本选择规则或时间切分，数字不可直接比较。覆盖率分母为训练期目录电影数，分子是所有纳入用户前 10 名中出现过的不同电影数。
